2. 할 일 2(밀도 상한): 이번엔 넣지 않았다. 선의 판을 CSS 화소 하나에 1.5 화소로 줄이면 선이 몸 가장자리와 판 화소 단위로 어긋나므로 기본은 지금처럼 상한 없음(화면 그대로), 칸만 둔다. 짓는 법: setLineResolutionLimit(cssPixelDensity) 같은 칸, beginLineIds 가 선의 판을 viewport x min(1, 상한 / devicePixelRatio) 로 짓고, 가면과 씨앗은 판 화소, 섞기는 point = (gl_FragCoord - viewport) x 배율 - 0.5, 거리는 1 / 배율 곱해 그리는 영역 픽셀로(섞기 셰이더의 toOutput 자리가 이미 있음), 찾기 반지름은 판 화소로 ceil(L x 배율 + 1). 모서리 어둠(ToonPostProcess.drawAmbientOcclusion)은 선의 판 width, height 를 그대로 쓰므로 같이 줄어든다.
3. 할 일 3(MRT): SE2 가르기에서 선의 판만 그린 프레임이 끔과 같은 17 이라 이번엔 하지 않았다. 아이패드는 05:00 뒤 같은 가르기(bench.html ?mode=prepass, post)로 재어 정한다. 설계:
   - 몸 셰이더(toonrenderer.js, 다른 작업자가 블록 줄을 고치는 중이라 이번엔 손대지 않음)에 layout(location = 1) out vec4 fragmentLine 을 더해 선의 판과 같은 부호(팔면체 노멀, 번호 14 비트, 꼴 2 비트)를 쓴다. 바깥선이 없을 때는 drawBuffers 에 둘째를 걸지 않는다(지금처럼).
   - 기본 프레임버퍼에는 둘째 판을 붙일 수 없으니 몸을 화면 밖 판(색, 선의 판, 깊이 텍스처)에 그리고 캔버스로 한 번 옮겨야 한다(화면 전체 복사 하나가 늘고, 타일 GPU 에서는 그 판들을 저장해야 함). MSAA 면 모든 첨부 표본 수가 같아야 해 선의 판을 정수 형식(RGBA8UI, 풀 때 한 표본을 고름)으로 둔다.
   - 차례가 몸 -> endLineIds -> drawOutline 로 바뀐다. 투명, 바깥선 껍데기 그리기는 둘째를 끈다(drawBuffers [COLOR0, NONE]). hasScreenOutline false 모형은 꼴 0 으로 번호만 쓴다.
   - 광부가 getLineTarget().lineTexture 를 읽는다(칸 강조 채움). MRT 로 가도 RGBA8, 노멀 rg 팔면체, 번호 b(낮은 8 비트)와 a 아래 6 비트, a 위 2 비트 깃발 부호와 같은 getter 를 그대로 낸다. 굵기와 꺾임 굵기가 0 이면 선의 판만 그리고 긋지 않는 동작도 그대로. (이번 고침도 셋 다 그대로다)
   - 득: 선의 판 장면 다시 그리기(광부 500 천 삼각형)의 꼭짓점 몫과 채움. 실: 몸 패스 화소마다 4 바이트 더 쓰기, 화면 밖 판과 옮기기. 유니티 URP 의 DepthNormals 미리 그리기 대 디퍼드 GBuffer 의 득실은 이번에 원문을 읽지 못했다(원문 미확인).
4. 미선짱 차례 (2) 프레임 첫머리 헛 패스(ToonPostProcess.begin 이 장면 MSAA 판을 비운 뒤 그림자와 선의 판으로 갔다 돌아옴)는 이번에 못 했다. 그리기 줄의 draw 가 선의 판을 몸보다 먼저 그리는데 begin 의 비우기가 그 앞이라 엔진 차례를 바꿔야 한다. 정석 꼴: ToonDrawQueue 에 그림자와 선의 판만 먼저 그리는 길(예: prepare(renderer, camera), draw 는 이미 했으면 건너뜀)을 더하고, 쓰는 차례를 prepare -> postProcess.begin -> draw -> end 로 문서와 예제에. 또는 begin 이 비우기를 적어 두고 그리기 줄이 장면 판에 처음 그릴 때 비움. jsgpupass 의 toonpassbench 근거 0.30 ms.
5. 판 불러오기와 저장: 그리기 줄이 캔버스를 비운 뒤 선의 판으로 넘어가므로(MSAA 캔버스 렌더 패스가 끊김) 캔버스 비우기를 선의 판 뒤로 옮기면 MSAA 판 저장, 불러오기 하나가 준다. toondrawqueue.js 와 게임 쪽 차례라 이번엔 손대지 않았다.
