Visual went to the other features block, VisualAsset and BunchAsset to the resources block. The exported names are the same except for the one new Experimental
- README, guide, ARCHITECTURE: updated to the new folders and removed the text calling 3D and toon 3D experimental features. (README's "3D (experimental)" is now "3D")
- Moves general-purpose features that webgame-rimminer had built and used separately on the game side into the engine. (Game code was not touched; the game keeps using its own as before)
- ShaderWarmer: shader pre-linking. At startup, links the same sources in the background with KHR_parallel_shader_compile and leaves them in the browser program cache, so the main thread does not stall when ShaderProgram later builds the same sources. Does nothing if the extension is absent. update() every frame, isFinished(), isSupported(). Attribute locations are given with the same attributeLocationTable as ShaderProgram
- Outline: a component that draws only the border. (Paint only fills the inside) Rounded rectangle border (setRoundSize) or circle border (setCircle); the line stays inside the content size. setColor(Color or "#rrggbb", "rgba(...)"), setLineWidth
- UIProgressRing: progress ring component. Following the node's shape (rounded rectangle; a circle when the roundness is half the size), draws the filled portion (setRatio) clockwise from the top center in the fill color and the rest in the background color. Perimeter points are computed only when the size, roundness or thickness changes
- UIHitArea: hit area expansion. UIHitArea.attach(buttonNode, minimumSize) places a transparent hit area as the sibling right behind the button, expanding its width and height to at least minimumSize. Pressing the expanded area calls the button's click notification, and it follows the button when the button is disabled or cannot be pressed. Tracks the button's position, size and pivot every frame. setClipNode can clip the expanded area to within a window or scroll area
- FrameProbe: slow device detection. After a wait period in seconds, observes frame intervals for a measurement period in seconds; the device is slow if 25% or more of frames exceed 1.4 times the target interval. (Constantly skipping every other frame, like 60 FPS on a 90 Hz display, is not counted as slow) restart, measureAgain; values are changed with setSeconds, setSlowFrameThreshold
- PointerCursor: mouse cursor. When enabled (PointerCursor.getInstance().setEnabled(true)), the engine sets the canvas cursor at the end of every frame. Over a UIButton (including while pressed) it is the button's cursor (pointer by default), otherwise the cursor set with setScreenCursor. registerImageCursor adds image cursors at 1x and 2x. Leaves the cursor untouched on touch devices. When disabled (default), behaves as before
- UIButton: notifies PointerCursor while the mouse is over it or it is being pressed. (Nothing happens if PointerCursor is disabled)
- Engine: calls PointerCursor.apply() at the end of the frame (after drawing the batches)
- Platform: isDesktopWeb() (not mobile, and not an iPad presenting as a Mac with multi-touch input), isCoarsePointer() (CSS pointer: coarse)
- ViewManager: getCssPixelScale(). How many CSS pixels one view unit spans on screen. (Used to compute the scale for enlarging only the UI layer on small screens)
- SoftShade, SoftShadeShape: soft shade component. Darkens the area behind text so it stays readable on bright backgrounds. Bakes a band (darkest in the middle, fading toward the top, bottom and sides) or a floor (vertical gradient, darkest at the bottom) into a small canvas and draws it stretched to the content size. Rebakes only when the size, shape, color or strength changes
- ShadowText: single-line text component with a shadow underneath. Bakes the text over the shadow into a single canvas and draws it, so the node's opacity applies to text and shadow as one layer. (With two Text layers, the shadow underneath shows through when faded) The shadow can be blurred (shadowBlur of setShadow), and on overflow the text shrinks down to setFitMinimumRatio to fit. Horizontal alignment and position use the same calculation as Graphic.drawTextEntry; vertical is centered. setFontFace, setTextDirection
- ShadowImage: image component with a shadow underneath. Draws the image (or an atlas piece via setImage(image, imageRect)) centered in the node preserving its aspect ratio, paints a shadow under the image's shape, and bakes them into one layer. setImageColor can tint the image a single color
- buildRGBAString(colorText, opacity): builds a canvas rgba color string from "#rrggbb" and opacity. (shadowtext.js)
- CameraGestures: camera gestures. Reads gestures for rotating, panning and zooming a 3D board or map independently from the canvas DOM events. Right mouse drag (horizontal rotates, screen width is one full turn; vertical tilts; releasing without dragging is a right click), middle drag (pan), two fingers (pan, pinch to zoom, twisting past a threshold rotates). Accumulated amounts are taken every frame with takePan, takeRotation, takeTilt, takeZoom, getZoomAnchor. isGestureActive during a gesture. Emulated mouse events right after fingers are lifted are ignored. setThresholds changes the thresholds and dispose detaches
- SoundSystem, setSoundSystem, readSoundSystem: background music and sound effects managed through a sound table. (Uses AudioManager's shared AudioContext and AudioAsset) Each row is { id, path or paths, volume, minimumInterval, isMusic, maximumVoices, pitchVariation, playSeconds, fadeOutSeconds }. Picking a recording different from the previous one among several, limiting simultaneous instances of the same sound, pitch variation, playing only the first few seconds and fading out, background music crossfade and continued playback, music and effect buses. Mute engages if any one of these holds: the user button, the page being hidden, window focus loss on touch devices (prevents iPhone audio freezing and repeating on app switch), or an external mute supplied via setExternalMuteProvider (platform SDK, ads); meanwhile the AudioContext is suspended. If it does not resume after unmuting, it is woken again periodically. setAutoplayAllowedProvider can prevent waking before a tap. update() every frame
- LanguagePack: language bundles kept as asset JSON. (Functions under the LanguagePack import name) Reads languages.json (language list, fallbackLanguage, and per language code, name, englishName, fontGroup, direction, aliases, countries, file) and the table for each language. If the language in settings is empty, uses the language given via setPreferredLanguageTag (reported by the platform), then the device language, and the default language if not in the list. A missing key falls back to the default language's text, and if missing there too, to the key itself. translate, formatText({name}), readTextDirection, isolateText (direction isolation), the html lang and the tab title (setDocumentTitleKey). setLanguagePaths sets the paths, and setLanguageLoadedHandler sets what to do after a language is loaded (fetching that language's font). Localization (in-code tables) is unchanged
- UIFont: groups font subsets for multiple scripts under one font name. (Functions under the UIFont import name) Registers a FontFace for each subset split by Google Fonts with that subset's character range (unicode-range), so only subsets containing characters used on screen are downloaded. The selected language's group is placed right before Latin so Han characters render in that language's font, while digits and English letters always use the Latin font. Weights are registered as only two, selected together through a range. Subsets for characters to be used are fetched in advance (loadUiFontText, requestUiFontText), and the first subsets are waited for only up to a set time. The remaining groups are fetched a little later. configureUiFont sets the name, list path, weights and wait time, and readUiFontFace reads the FontFace to give to Text and ShadowText
- ToastMotion, attachToastMotion, readToastSeconds: enter and exit motion attached to a notification node. show(text, seconds, applyText) slides in from the outer side (setEnterSide, top or bottom) while growing slightly and settling back, then after staying, floats up, fades out and disables the node. If different text arrives while shown, the previous one moves aside quickly; if the same text arrives again, only the time is refilled and it pops. Movement stays only around the placed position as the reference. readToastSeconds lengthens the stay time for longer text. (UIToast builds queued pill notifications by itself; this animates a notification node built by the game)
- ButtonMotion, ButtonMotionStyle, attachButtonMotion, setButtonMotionArea, shakeButton: button feedback. Attached after UIButton, it reads the button state and scales the node up and down around its center. The normal style grows on hover, shrinks while pressed and pops on release. The inset style (inside windows) does not grow; while hovered it brightens the background and adds a white inner border. When not pressable, shakeButton shakes it left and right. The style is set per button (setStyle) or on an ancestor node with setButtonMotionArea. Touch devices do not use hover. When there is no feedback, the node is left untouched so it does not conflict with other effects. To make decorations on the button light up in their own shape, set a function with setLitHandler
- ToonMesh(graphics3d/toon/meshbuilder.js): builds vertex arrays for drawing toon 3D (clay-like single-color material and outlines). Puts box, rounded box, cylinder, sphere, lathe, capsule, torus and octahedron shapes into MeshBuilder as one mesh, transformed by position, rotation and scale. Vertices are position 3, normal 3, color 3 (sRGB), material 2 (emissive, unlit), pattern 4 (pattern index and color, meaning defined by the shader). Outlines are stored separately as a shell pushed out by the same thickness at every point (inverted hull), pushed so it does not stick out too far at corners. Triangle winding is corrected using the normal so the outside is the front face. Skinned models store bone indices and weights separately
- ToonGlb(graphics3d/toon/glbmeshreader.js): reads GLB painted with material colors without textures into MeshBuilder arrays. (readGlbArrays, per node readGlbNodeArrays, node info readGlbNodeInfos) Reads baseColorFactor as sRGB, emissiveFactor as emissive, and outline and basic from material extras. Reads the skeleton (skin) and motion (animations, extras), and writeSkinPose computes bone matrices for a single moment. (Blending with the previous pose, sway scale) Separate from the engine's SkinnedModel (textured PBR)
- ToonRenderer(graphics3d/toon/toonrenderer.js): toon renderer that draws ToonMesh and ToonGlb arrays. Sun (direction, color) and ambient light blending sky and ground colors, cel shading bands with setBandCount, per-vertex emissive and unlit, per-model tint and opacity; the outline shell draws back faces only. For skeletons, bone matrices from writeSkinPose are passed to drawMesh as jointMatrices. (Up to 96, same as the engine SkinnedModelRenderer) beginFrame records the previous draw state and endFrame restores it, so it can be inserted between engine 2D drawing (after flushSpriteBatch). readProgramSources provides the sources to pass to ShaderWarmer. Rebuilt from the board renderer of webgame-rimminer with game-specific parts such as ground patterns and screen-space lines removed
- ToonRenderer: GPU instancing (drawMeshInstanced, per instance { modelMatrix, tintColor }, for both body and outline), off-screen culling (model bounding sphere against the frustum; instances are culled one by one and only the remaining ones are uploaded, options.isCulled), shadows (beginShadowPass, drawMesh draws depth only, endShadowPass restores the framebuffer and viewport, received with 3x3 PCF via setShadow(ShadowMap)), HDR output (setHdrOutput), drawn count, culled count and draw calls for one frame (getFrameStatistics), extractFrustumPlanes
- ToonPostProcess: HDR finishing. Applies BloomEffect to the scene drawn into a half-float RenderTarget, and outputs to the screen with exposure, approximate ACES tonemapping and sRGB gamma. (begin, end, setExposure, setBloom) Same setup as the Rust vanilla-engine
- Rendering: reduces per-frame object creation and per-draw-call work when drawing nodes and Paint. Rendering results are the same and caller usage is the same. (Capturing the bench scene below and the examples uishowcase, uisample, spriteeffects, particleeffects, timelineshowcase at the same frame with a fixed clock gives screen pixels identical to before the change) Measured at the same time in Chrome (headless, real GPU) on a scene of 8,000 moving nodes drawing rounded rectangles with Paint (the same-spec comparison bench of rustgame-test), drawing goes from 78.0 ms to 13.0 ~ 14.4 ms, the frame from 90.1 ms to 23.9 ~ 26.3 ms, and the node count holding 60 FPS from 1,000 to 4,000 ~ 6,000. (Measured on one PC; game logic time is unchanged)
- Graphic.drawRoundRect: computes the cos / sin of the 36 vertices from a table built once at module load, and writes vertices directly from coordinates written into a reused slot instead of creating a Vector2 array. (Removes 72 trigonometric calls, 36 Vector2 and 4 corner objects per node per frame) The table is built with the same formula as before (cos / sin of engine base/math.js), so vertex values are bit-identical. buildRoundRectPositions also uses the table. (The returned Vector2 array is still newly created as before) drawRoundRect no longer goes through buildRoundRectPositions
- Graphic: writeRoundRectPositionData(rect, roundSize), drawRoundRectPositionData(color). Writes rounded rectangle coordinates into a module slot, and draws the fill from that slot. (Used by drawRoundRect)
- Paint.draw: instead of creating one Rect (including its inner Vector2) and a copy of the content size on every draw, reuses a single rectangle kept in the module and receives the size via WorldNode.copyContentSizeTo. The rectangle passed to graphic's draw functions changes when the next Paint is drawn. (Nothing in the engine holds on to the received rectangle)
- WorldNode: copyContentSizeTo(target). Writes the content size into target without a copy. For subclasses that override getContentSize (UINode etc.), writes the value that function returns
- pushTransform of TransformNode, WorldNode: reads position, scale, pivot and content size without copies. (Four Vector2 per node per frame) TransformNode.applyLocalTransform(graphic) applies the local position, rotation and scale. Subclasses that override those getters are still read through the getters as before
- TransformMatrix: rotate(0) and scale(1, 1) return without computing the matrix. (The result is the same; they are called on every draw even for nodes that do not rotate)
- Graphic.pushState / popState: instead of creating a matrix copy and a state object on every save, writes the current matrix object and its values into a slot pre-created for each stack depth. On restore, writes the values back into the matrix object from save time and makes it the current matrix again. So a matrix obtained via getTransformMatrix() is still the current matrix after restore. (Previously, restore switched to the saved copy, so a previously obtained matrix was no longer the current matrix)
- TransformNode.setLocalPosition / setLocalScale, WorldNode.setPivot / setContentSize: copy the values into the owned vector instead of cloning the given vector. Getters still return clones as before, so the owned vector does not leak out
- Rect: the constructor and create() no longer clone freshly created Vector2 a second time through setters. (Rect.create goes from eight Vector2 to two)
- Color.clone(): creates a new Color by copying rgba directly, without going through Reflection.clone. (Like Rect.clone, returns a Color rather than a subclass; there are no Color subclasses in the engine) Called on every draw in places such as setFillColor
- Reflection.clone: scans the list of property names that have both a getter and a setter only once per prototype and reuses it. (Previously walked the prototype chain on every call) Copy order and values are the same
- Object: removes the private fields (#instanceId, #isDestroyed). The unique identifier is put into a module WeakMap on the first getInstanceId() call. isDestroyed() is always false as before. (destroy() did not leave a destroyed flag) Removes two fields that were filled every time any engine object was created
- Graphic.drawVertices: looks up uniform locations (modelMatrix, mainColor, tintColor, globalAlpha) only when the shader program changes, rather than by name on every draw call. (uploadDrawUniforms) The default program's tint and global alpha are not uploaded again if equal to the last uploaded values. Uploaded values are forgotten at frame start (applySettings) and when the program changes, and are always uploaded for a swapped-in program (setShaderProgramOverride). If a game uploads the default program's tintColor, globalAlpha uniforms directly, the next draw call may not correct those values. (Nothing in the engine does so)
- Engine: Counts the maximum FPS limit (EngineConfiguration.maximumFramePerSecond) by the number of processed frames. The number of frames processed since counting started sets the slot of the next frame (start time + count × interval), and only frames arriving more than 4 ms before their slot are skipped. Backlog is processed on the next frame so the average reaches the maximum FPS. Previously, a frame was skipped if less than the interval minus 4 ms had passed since the last processed frame, and the reference was reset to the time of the processed frame, forgetting the backlog, so the limit was off when the refresh rate was not divisible by the maximum FPS. (At 60 FPS, 90 Hz skipped every other frame for 45, 144 Hz gave 72, 75 Hz skipped none for 75) When behind by more than one frame (window hidden and restored, etc.), does not catch up in a burst and restarts counting from that time. Processing a frame that arrives less than 1 ms before its slot restarts counting from that time, so on displays whose refresh rate is almost the same as the maximum FPS (60.05 Hz, etc.), small leads no longer accumulate into an occasional skipped frame. Changing the maximum FPS restarts counting. 60 FPS on a 60 Hz display and maximum FPS values that divide the refresh rate (30 FPS at 90 Hz, etc.) are the same as before.
