# 0.4.0

## Summary

- Folder cleanup: moved the grown-up features that were in src/experimental (3D, toon 3D, animation, collections and more) to the same folders as the Rust vanilla-engine. Games that use import.js keep working as is, and games that imported files directly by path switch to the new paths.
- From games into the engine: general-purpose features that the shipped games (webgame-rimminer, aberrant, steamgame-apocalypsesurvival, space-creature, retrogame-foundyou) had built separately are now part of the engine. These include window stacking (UIWindowLayer, UIWindow, UIConfirmWindow), loading, saving and time (AssetLoader, LoadingProgress, LocalStorage, PersistedStore, FixedStepper), input actions (InputActions), the sound table (SoundSystem), language packs and fonts (LanguagePack, UIFont), button and toast motion (ButtonMotion, ToastMotion) and the mouse cursor (PointerCursor).
- Toon 3D: rebuilt toon shading and the screen-space outline (ToonScreenOutline) in the standard form of real-time toon rendering. Toon effects (ToonVfx), HDR finishing (ToonPostProcess) and the shadow atlas (ShadowAtlas) are also in.
- Rendering: sprite batching and off-screen culling are on by default. Code that uses Graphic directly outside the engine loop calls flushBatch() after drawing.
- Matching the Rust version: brought in the general-purpose features that only the Rust version had so the public APIs of the two engines match, and fixed the bugs the two engines shared in both.
- UI: UIInputField handles word movement, word deletion and word boundaries like Chrome, and supports multiline input like a Chrome textarea (setMultiline) and engine undo and redo. UIDocument writes registered names so a minified bundle gives the same document, and registerEditorTypes() registers the UI editor's types in one call.
- Scene and Engine: widgets on nodes receive touches whatever the scene type. The view transform is applied before each scene draws, which fixes scenes that directly extend Scene drawing only in the top-left quarter of the canvas on screens with a device pixel ratio of 2.
- Docs: the data the site builds each version's documentation from (the public API docs/api/0.4.0.json, the guide docs/guide/0.4.0) and the tool that extracts it, tools/apidoc.cjs.
- Migration: where the public API or its usage changed, the line says how to migrate. (Scene touch, FbxLoader names, scene draw coordinates, Singleton, Color, JsonAsset.load, List and Dictionary callbacks, ToonScreenOutline, toon shading, isVisible, ToonVfx position, image path, Scene background, viewScaleMode default)

## Changes

- Sound streaming load (the same shape as Unity AudioClip's Load Type, Unreal sound wave streaming, and on the web an HTMLMediaElement connected into the graph with a MediaElementAudioSourceNode): added the load type AudioLoadType (automatic, decompressOnLoad, streaming) and setLoadType, getLoadType, isStreaming, getStreamUrl to AudioAsset. Until now every sound was fully decoded to PCM with decodeAudioData, so one 3 minute stereo background track held about 61 MiB (float32). Streaming lets a media element decode the compressed file bit by bit, and AudioPlayer connects one media element per player to the same GainNode. Play, stop, loop, volume, mute, rate (pitch changes too), position (getTime, setTime) and end (isPlaying turns false) behave the same as a fully decoded sound, and when the audio context stops (hidden tab, mute) the media element pauses too and then resumes. The AudioAsset default stays fully decompressing (decompressOnLoad, the same as the Unity AudioClip Load Type default), and only assets that choose automatic stream files larger than 1 MiB (AUTOMATIC_STREAMING_BYTE_THRESHOLD) (it checks the Content-Length header first and does not download the body). The engine SoundSystem sound table takes a loadType field, and without it background music (isMusic) uses streaming and sound effects use decompressOnLoad. Code that uses AudioAsset directly calls setLoadType to stream. Checked on real devices (iPhone SE 2 and iPad mini 6, iOS 27.2.1): sound plays after the first tap (RMS 0.07 to 0.14), media element play() was rejected 0 of 62 times, playback resumes after the tab is hidden and shown again, looping works, and loading took 137 ms on the SE 2 against 8,618 ms for full decoding. Measured with a 3 minute 128 kbps MP3 in headless Chrome on Mac: full decoding took 169 ms to load and +154 MB of Chrome process memory, streaming took 7 ms to load (metadata only) and +11 MB (+29 MB while playing), and sound started within 5 ms in both.
  - Migration: background music played through the engine SoundSystem now streams when its sound table row has no loadType, so code that used getAudioBuffer() of that asset directly gives the row loadType: "decompressOnLoad". Code that uses AudioAsset directly has nothing to change (the default is still full decoding) and calls setLoadType(AudioLoadType.streaming) to stream. getAudioBuffer() of a streaming asset is null.
- Bone pose hook (the same shape as Unreal AnimBP's Transform (Modify) Bone and bone overrides in Unity's LateUpdate): added a seventh argument poseAdjust to writeSkinPose. After the animation is sampled and blended, and before the skin matrices are built, it modifies each bone's local transform (translation, rotation, scale). A function is called with (locals, skeleton) and makes the changes (the arrays in locals belong to that call only, so modifying them in place does not change the skeleton's rest pose), and an array is applied as a per-bone modification table ({ nodeIndex or name, translation, rotation, scale, mode, weight }). Added adjustBones(locals, skeleton, modifiers), which applies the table, and the modification mode BoneModifyMode (add adds translation in parent space, multiplies rotation after in the bone's own space and multiplies scale, replace sets the given value). weight is the ratio between before and after the modification. Without a hook the result is bit-for-bit the same as before, and modifying one bone changes only that bone and the bones below it.
  - Migration: none. (new argument, the default is unchanged) Games that copied the engine's writeSkinPose to add a hook delete the copy and pass the same function as the seventh argument of the engine's writeSkinPose.
- 3D camera shake (the shape of Unity Cinemachine Impulse and Unreal Camera Shake): added CameraShake. Each shake from add(options) takes the strength of 3 position axes and 3 rotation axes (pitch, yaw, roll) (amplitude, rotationAmplitude, per-axis shares positionAxes, rotationAxes), frequency (frequency, default 10), duration (duration), attack (attack), decay ((1 - age / duration) to the power decayExponent, default 2), age (age, an event seen late added with that age continues with the same values as if added from the start, negative starts later) and seed (seed). The signal is two sine waves with slightly different frequencies per axis, live shakes are summed, and the same seed gives the same values. It has update(seconds), read() ({ position, rotation } in camera local axes), isShaking and clear. As places to apply it, added Camera3D.setViewOffset(position, rotation) (an offset in camera local axes applied last to the view matrix, on both the computed path and raw matrices, getEyePosition is the value before the offset) and createOffsetViewMatrix(viewMatrix, position, rotation), which applies it to a view matrix the game computed. ToonVfx's 2D shake (addShake, readShake) and Shaker are unchanged.
  - Migration: none. (new feature) Games that computed shakes themselves keep one CameraShake, call add per event and update per frame, and apply read() with Camera3D.setViewOffset or createOffsetViewMatrix. Shakes that were added in world axes become camera local axes (x right, y up, z back).
- glTF quantized mesh reading (KHR_mesh_quantization): the toon GLB readers (readGlbArrays, readGlbNodeArrays, readGlbNodeInfos) and SkinnedModel read GLB files whose vertex attributes are stored as integers. Normalized integers are divided with the glTF spec formulas (signed ones as max(c / 127, -1), max(c / 32767, -1)) and non-normalized integers are read as is. Position dequantization comes from the node transform or inverseBindMatrices, and texture coordinates get the material texture's KHR_texture_transform baked in. Normalized integer rotations in animations are read too. An unnamed mesh node belongs to the part of its named parent node (the leaf node a quantizer adds for the dequantization transform). If extensionsRequired lists an extension the reader cannot read (EXT_meshopt_compression, KHR_draco_mesh_compression and others), it throws a clear error. The Rim Miner mining ship model with gltfpack's default quantization (no compression) goes from 1.78 MB to 1.15 MB as a file and from 1.06 MB to 0.58 MB zipped. (tests/graphics3d/meshquantization.test.mjs)
  - Migration: none. (New feature)
- Capture mode determinism (same as the Rust edition): in capture mode (?capture=), the 0.3 second loading screen wait after a scene loads and the minimum display time wait of GameScene and UIScene are counted every engine frame on the engine clock (1/60 second per frame) instead of real time. The scene is initialized at the head of the frame where the 0.3 seconds are reached and drawn from that frame, as in the Rust edition, and images are uploaded at once. While loading (anything that takes real time, such as downloading assets), the frame number and the clock do not advance, so counting starts once everything has arrived. Capturing the same example twice gives byte-identical images for the same frame number.
  - Migration: none. (Only capture mode changes. Waiting on the engine clock inside a scene's async load never resolves in capture mode, so move such waits after initialize)
- Batched drawing names same as the Rust version: Graphic.setSpriteBatchingEnabled, isSpriteBatchingEnabled and flushSpriteBatch are now setBatchingEnabled, isBatchingEnabled and flushBatch (Rust set_batching_enabled, is_batching_enabled, flush_batch). A batch holds not only images but also shapes, text and vertex color quads, so 'sprite' narrowed the meaning. flushSpriteBatch is removed.
  - Migration: graphic.setSpriteBatchingEnabled(x) becomes graphic.setBatchingEnabled(x), isSpriteBatchingEnabled() becomes isBatchingEnabled(), and flushSpriteBatch() becomes flushBatch().
- Removed the toon 3D namespaces ToonMesh and ToonGlb. The functions and classes of the mesh builder (meshbuilder.js) and the GLB reader (glbmeshreader.js) are exported directly by name (same as the Rust version). In the Rust version ToonMesh is the renderer's mesh (what ToonRenderer creates), so the same name is not reused for another meaning. flushSpriteBatch is removed too.
  - Migration: drop the prefix, so ToonMesh.MeshBuilder becomes MeshBuilder, ToonMesh.createBoxGeometry becomes createBoxGeometry, and ToonGlb.readGlbArrays becomes readGlbArrays. Change import { ToonMesh } to import the names you use. flushSpriteBatch() becomes flushBatch().
- Top-level names as the same set as the Rust version: import.js no longer exports the deprecated Camera (Camera2D covers it), SceneManager (internal to the engine, Engine.getSceneManager is hidden too), List, Dictionary, Queue, Stack (use the language Array and Map, the Rust version uses Vec, HashMap, VecDeque) or Singleton. Added Engine.getAllLoadedScenes() (Rust get_all_loaded_scenes). The toon mesh builder and GLB reading functions are exported by name as in the Rust version (MeshBuilder, shape functions such as createBoxGeometry, createPartMatrix, readColorValues, readGlbArrays, readGlbImages, decodeGlbImage, readGlbNodeArrays, readGlbNodeInfos, readAnimationSwing, writeSkinPose). The namespaces ToonMesh and ToonGlb stay as deprecated and are removed in the next version (ToonMesh in the Rust version is the renderer's mesh, so one name does not get two meanings).
  - Migration: engine.getSceneManager().getAllLoadedScenes() becomes engine.getAllLoadedScenes(), and loading and unloading scenes use engine.loadScene, unloadScene, unloadAllScenes. Camera becomes Camera2D. List, Dictionary, Queue, Stack become Array and Map. For ToonMesh.MeshBuilder, ToonMesh.createBoxGeometry, ToonGlb.readGlbArrays and the like, delete the leading ToonMesh. or ToonGlb. and import that name.
- Public features that existed only in the Rust version (same names): ViewManager.limitRenderPixelRatio(devicePixelRatio) (the ratio with the cap applied, used by calculateViewRect), GraphicsQualityGovernor.applyPageQuery(liteKey) (override from the query of the current page URL, same as applySearchText(location.search)), DevTools.inspectNode(node) (shows the panel, switches to the Node Hierarchy tab, expands the ancestors and selects the node), Graphic.measureTextWithFontString(fontString, text) (measures without changing the current font), LocalStorage.setStorageDirectory(storageDirectoryPath) (the save folder of the Rust version on desktop, does nothing in this version because it uses the browser storage).
  - Migration: none. (New features)
- UIDocument becomes an instance without global state (same as Rust UIDocument::new): the type tables (components, nodes), the image resolver and the lists that hold node references and images, which were module globals, are held by each document object. new UIDocument() registers the engine's default types, and setImageResolver, resolveImage, serializeNode, deserializeNode, toJsonText, fromJsonText, collectGeneratedComponentTypes, getComponentTypeNames, registerNodeType, registerComponentType, registerEditorTypes, saveByReflection and loadByReflection, which were static, become instance methods. getReflectedProperties, findNodePath and findNodeByPath have no state and stay static. An image that is not found gives a warning. getComponentType, getSerializeRootNode, saveNodeReferences and loadNodeReferences are now private (internal functions Rust does not have). Added UIListView.setTemplateNodeWithDocument(templateNode, uiDocument) (setTemplateNode uses a new document), and Visual.createNode takes a document (same as Rust create_node). UI Editor and Visual Editor each hold one document.
  - How to migrate: where UIDocument was called statically, such as UIDocument.fromJsonText(text), make a document and call it on that document. const uiDocument = new UIDocument(); uiDocument.registerEditorTypes(); uiDocument.setImageResolver(resolver); const rootNode = uiDocument.fromJsonText(text). Registrations and the resolver apply only to that document, so read with the same document. Instead of a resolver you can load the images first with await Promise.all(uiDocument.loadImages(text)). Where UIDocument.getComponentType(name) gave a constructor to attach, attach with uiDocument.createComponent(node, name). Change visual.createNode() to visual.createNode(uiDocument), and list templates with game components to listView.setTemplateNodeWithDocument(template, registeredDocument).
- ToonView3D screen rectangle and output (same as Rust Rect and ToonViewOutput): getScreenRect() returns a Rect (a copy) instead of an { x, y, width, height } object. The draw function becomes (renderer, camera, screenRect, webGL2RenderingContext, output): screenRect is the Rect to draw in, and outputFramebuffer and outputViewport, which rode on the screen rectangle object, move to the fifth argument, an output object ({ outputFramebuffer, outputViewport }).
  - How to migrate: in draw functions, change screenRect.x, y, width, height to screenRect.position.x, position.y, size.x, size.y, and screenRect.outputFramebuffer, screenRect.outputViewport to the fifth argument output.outputFramebuffer, output.outputViewport. (ToonPostProcess.end(output.outputFramebuffer, output.outputViewport))
- Public functions only the original had (same surface as Rust): WorldNode.isComponentDrawCulled, Camera3D.refreshMatrices and LocalStorage.readStorage, used only internally, are now private (Rust does not expose them either; the getters recompute the matrices themselves). UIButton.setStateEvent, which did nothing, is removed. Rust gains WorldNode::copy_content_size_to and ShadowAtlas::get_light_count with the same names.
  - Migration: delete camera.refreshMatrices() calls (getViewMatrix and getProjectionMatrix compute on their own). Delete setStateEvent calls (it did nothing). Hook per-state work with setPressedEvent, setReleasedEvent and setClickEvent.
- Default font (same as Rust default_font_url and the font name "default"): the default of EngineConfiguration.defaultFontUrl changes from the DOSGothic address on jsDelivr to an empty string, so the engine no longer always fetches a font it does not use. When an address is given, that font is added under the font name "default" (before, "DOSGothic"). Text with no font (Text, ShadowText, DynamicFont, buildFontString(null)) uses the engine default font chain DEFAULT_FONT_FAMILY_STRING ('"default", ' followed by SYSTEM_FONT_STRING) instead of the system font chain, so like Rust "32px default" it picks the default font when there is one and the system font otherwise. The statistics overlay also draws with "16px default".
  - Migration: games that used DOSGothic give a font address to defaultFontUrl (its name is "default") or add "DOSGothic" with a FontAsset. Places that picked it by name, such as "16px DOSGothic", add it with a FontAsset or change to "16px default".
- Baked components keep colours as Color (same as Rust ShadowText, SoftShade, ShadowImage): ShadowText, SoftShade and ShadowImage keep colours as Color instead of a "#rrggbb" string. The setters still take both a Color and a colour string, and copy the Color they get. SoftShade.getColor() returns a Color, ShadowImage.getImageColor() returns a Color or null, and UIDocument writes ShadowImage's ImageColor as an array of four numbers ([r, g, b, a]) like Rust (old documents with a colour string still load). The alpha of ShadowText's text colour is the text opacity. The module function readColorText is now readColor (returns a Color), and buildRGBAString takes a Color.
  - Migration: where softShade.getColor() or shadowImage.getImageColor() was used as a string, append .toHEXString().
- Screen fade hold (same as Rust ScreenFadeHold, fade_screen_with_hold): added ScreenFadeHold (release, isReleased) and GameScene.fadeScreenWithHold(onDark).   - Migration: none. (New feature, an onDark that returns a Promise works as before)

  - Migration: cooldown.use() becomes cooldown.activate(), pass.use() becomes pass.useProgram(), shaderProgram.use() becomes shaderProgram.useProgram(), pointerGesture.move(x, y) becomes pointerGesture.movePointer(x, y), action.loop(...) becomes action.repeatWhile(...), and Tween.easingFunction.quadratic.in becomes Tween.easingFunction.quadratic.easeIn (out and inOut become easeOut and easeInOut).   - Migration: rename DEVTools to DevTools (the old name is gone). Code that called setTextAntialiasEnabled(value) from textstringtexturecache.js directly calls graphic.setTextAntialiasEnabled(value).

  - Migration: none.
- UIInputField multiline input and undo (same as set_multiline, set_line_height, set_tab_size, get_scroll_top, set_scroll_top, can_undo, can_redo and the TextEditBuffer grouping rules of the Rust edition): with setMultiline(true) it is a multiline input like a Chrome textarea (DOM input uses a hidden textarea). Text is split by line break characters and width like white-space: pre-wrap, overflow-wrap: break-word, and line break opportunities are read from Chrome's own line breaking, giving the same lines as the Rust edition (the same computation as the 30 texts captured from a Chrome 158 textarea). Enter inserts a line (no submit), up and down keep the horizontal position of the first vertical move, and PageUp, PageDown, Home, End (start and end of the visible line), Ctrl (Cmd on Mac) + Home, End (up, down on Mac) and the Mac Home, End, PageUp, PageDown scrolling match the Rust edition. When it overflows it scrolls to keep the caret visible, scrolls with the wheel and by dragging the thumb, and draws a thumb. With classic scrollbars (Windows, Linux, Mac classic setting) the text width shrinks by the scrollbar thickness when it overflows, like a Chrome textarea. Added setLineHeight (null for CSS normal), setTabSize (default 8), getScrollTop and setScrollTop. Undo and redo use an engine history in both canvas mode and DOM input (Ctrl (Cmd on Mac) + Z, Ctrl (Cmd on Mac) + Shift + Z, Ctrl + Y on Windows and Linux, also Alt + Backspace on Windows, consecutively typed characters are one group, moving the cursor breaks the group, paste and cut are separate groups, up to 1000). DOM input blocks the browser undo keys and historyUndo, historyRedo and uses the engine history, so a paste from the context menu can be undone too. It does not undo during IME composition, and committed text joins the preceding insert text group. Added canUndo() and canRedo(). setText clears the lists
  - How to migrate: none. (new feature, single-line field behavior is unchanged) A game that used Ctrl (Cmd on Mac) + Z itself while a canvas mode field is focused now has the field take that key.
- Image decoding and uploading moved to load time (the same shape as Unity and Unreal uploading at load time, and createImageBitmap on the web): when ImageAsset loads, it receives the bytes and decodes them off the main thread with createImageBitmap alongside the image element (Chrome decodes a Blob on a worker thread), and uploads that on the first upload and then closes it. Uploading the image element with texImage2D made Chrome decode it again on the main thread right there, so the first drawn frame of a new screen hitched. SceneManager uploads the loaded images to the GPU during the loading screen after a scene's load finishes, split 2 milliseconds per frame (Unity asyncUploadTimeSlice default) (Graphic.prepareLoadedImages, overlapping the minimum 0.3 second wait). Canvases made in code are uploaded in the scene's load with Graphic.prepareImage. The screen result is unchanged: only formats whose ImageBitmap result is byte-identical to uploading the image element are pre-decoded (8-bit PNGs that have no alpha, no color chunk or only an sRGB chunk, JPEG, WebP without alpha or animation), and the rest (PNGs with alpha and a non-sRGB color profile, 16-bit PNGs, WebP with alpha, GIF, AVIF, SVG) upload the image element at load time. Chrome 158 decodes an ImageBitmap premultiplied and then converts color, while texImage2D decodes unpremultiplied, converts color and then premultiplies, so such images differed by up to 6/255. The first drawn frame of an image-heavy scene (16 PNGs of 1024, 8 JPEGs of 2048, Mac mini M2 Pro headless Chrome 158 ANGLE Metal) went from 336 ms to 1.4 ms.
  - How to migrate: nothing. ImageAsset.getImage().src is a blob: address if the bytes were received (the asset path is getAssetPath). If the bytes cannot be received, as with file://, the address is put in as before. A missing image (404) is rejected right away with Load fail without building an image element.
- Discarding attachments that are not read again at the end of a pass (invalidateFramebuffer, the same shape as Unity and Unreal not storing attachments with the store action at the end of a pass): RenderTarget.resolve() discards the multisample color and depth after resolving, or a depth renderbuffer that is not a texture when not multisampled, and the opacity layer (beginOpacityLayer) discards its depth and stencil when it ends. Mobile tile GPUs do not write those attachments to memory. The scene target of ToonPostProcess and the render scale target of ToonView3D take this path. The screen result is unchanged and there is almost no difference on desktop GPUs. The depth of the screen outline's line target is read by seed selection, and the post process depth texture is read by compositing, so they are not discarded at the end of those passes.
  - How to migrate: code that kept drawing into the same multisample target after resolve() without clearing keeps it with resolve(true).

- Text drawing uses a glyph atlas (the same model as the Skia glyph cache, Unity TextMeshPro dynamic atlas and Unreal font cache): instead of baking each string whole on a canvas and uploading one texture per string, each grapheme chunk is baked once per font (mode, font string, bake scale, line width) into atlas pages (1024 x 1024, glyphs go into the newest page and a new page opens when it is full, up to 8, beyond that the least recently used page is cleared), and strings are drawn as glyph quads through the sprite batch. A new string bakes only glyphs it has not seen, and text on the same page is one draw call. The pixels match Chrome drawing the whole string with fillText: Chrome (Skia) rasterizes glyphs separately at 4 horizontal subpixel positions (rounding 1/8) and stamps them at integer positions, so glyphs are keyed by (grapheme chunk, 1/8 position slot) and placed where measureText puts them (width of the previous chunk joined with this one minus this chunk's width, kerning included). Latin, Cyrillic and similar letters that can form ligatures are baked per word, right-to-left text (Arabic, Hebrew) and fonts over 256px per string. In headless Chrome (macOS; Korean, English, digits, mixed, emoji, ligatures, Arabic, Thai, Devanagari, Cyrillic, several sizes and weights, outline, device pixel ratio 1 and 2) the pixels that differ from before are 6 at 1:1 (setTextBakeScaleStep(0), setTextPixelSnapEnabled(true)) ratio 1 (at most 4 levels) and 2 at ratio 2 (1 level), from 8-bit compositing where glyph ink overlaps. Text placed at fractional positions or stretched can differ by up to 10 levels where neighbouring glyph ink touches within one texel, because linear filtering runs per glyph (57 pixels with the default settings at ratio 1). Ink taller than the line (the acute on Ǻ, stacked combining marks, tall serif accents) is not clipped, as with Chrome fillText: the string rectangle and each glyph cell span the larger of the font box and the ink (actualBoundingBox) plus a padding of 2 (outlines add half the line width, rounded up), and the baseline stays where it was, so line layout and alignment do not change (before, the font box clipped it and a 32px Ǻǻ line differed in 252 pixels; now 0 at ratio 1 and 2). The top and bottom row of each cell repeat the cell edge rows, so at fractional vertical positions linear filtering does not sample a neighbouring atlas row, and blank chunks (spaces) are not baked. A 50-line text screen goes from 100 draw calls to 1, and 300 new strings made of known characters go from 300 bakes (texture uploads) to 0. - ToonScreenOutline: rebuilt the screen-space outline in the standard form of real-time toon rendering. (It is the engine's baseline, not a form fitted to one game)
  - Detection: checks once at each boundary between a pixel and its four direct neighbors in the line buffer (normal, line id, depth), and places the line at the middle of that boundary. (The G-buffer edges of Saito, Takahashi 1990, the four-neighbor check of the Unity Shader Graph example) Until now crease lines were checked with the normal of a single point creaseRadius away from the center pixel, so bands appeared on both sides of a crease, enlarging the half-size buffer produced dotted lines and a parallel second line, and one more band appeared inside the silhouette of round surfaces
  - Depth: unprojects the two neighboring pixels to view-space positions and detects occluded silhouettes by the distance from each other's tangent plane. No false lines appear on floors seen at a grazing angle or around round surfaces. (The Roystan approach, which adjusts the threshold by viewing angle, done with the tangent plane) Adds twice the pixel size at that depth to the threshold
  - Widening: propagates the distance to the boundary segments with jump flooding (Rong, Tan 2006). The number of steps is log2 regardless of width. (Ben Golus, The Quest for Very Wide Outlines) Outer lines and crease lines are propagated separately so they get separate widths. The previous 3-pixel radius limit is gone
  - Blending: each pixel of the drawing area is covered by clamp(width / 2 - distance + 0.5, 0, 1), from the distance to the nearest boundary. Since the distance is measured in the drawing area even when the line buffer is reduced, widened lines do not break up
  - Per model: options.hasScreenOutline of drawMesh, drawMeshInstanced (when false, it emits no lines and only occludes the lines behind it), options.hasCreaseLine, options.isMirrored (if not given, the winding is flipped by the determinant)
  - How to migrate (the public API changed)
    - setCrease(angle, intensity, continuation pixels) → setCrease(angle, width, intensity). Width is in the units of setWidth with default 1, and intensity is 0 ~ 1 with default 1. Continuation pixels (creaseExtent) are gone. (Not needed since only the gap across one pixel is checked) A look similar to the old setCrease(60, 0.5, 2) is setCrease(60, 1, 0.8) in pixel units, and in world units a width about half the outer line width (setCrease(60, 0.011, 0.8) for setWidth(0.022, world)). Because the width is in the units of setWidth, giving 1 in world units makes a line 1 meter wide
    - setDepthThreshold(depth threshold, contact threshold) → setDepthThreshold(depth threshold). Its meaning changed to the tangent-plane distance. (A world length; the same value can be passed as is) The contact threshold (contactTolerance) is gone. Since the line is placed at the middle of the boundary, there is no need to decide which side to draw it on
    - The meaning of setWidth: the width of a single line, covering half on each side with the boundary at the center. (Until now that width was only on the outside of the silhouette) Default 1.5 → 2 pixels. To match the outer thickness of the old look, give twice the value. To match the overall look of the line (the sum of coverage), use about 0.9 times rather than twice. (Compared by running the old shader on the same line target: Aberrant's old values 0.022 m, crease 60 degrees .5 2 px are closest to setWidth(0.020, world), setCrease(60, 0.016, 0.5), setDepthThreshold(0.08); the coverage sums differ by 1 % in the toonstyle scene at 1280 x 720)
    - setSampleCount, TOON_SCREEN_OUTLINE_MAXIMUM_SAMPLES, TOON_SCREEN_OUTLINE_MAXIMUM_CREASE_SAMPLES are gone. (With jump flooding the number of steps is set by the width on its own) For a lightweight path, lower only setResolutionScale
    - getOutlineRadius() → getLineWidths() (drawing area pixels of [outer line, crease line])
    - Line id limit 65535 → TOON_SCREEN_OUTLINE_MAXIMUM_LINE_ID (16383). The top two bits of the line buffer's a channel hold the per-model options
    - The maskTexture of getLineTarget() is gone. Instead seedTextures (two RGBA16UI), seedIndex (the side that finished widening)
    - drawOutline sets the viewport to the drawing area from beginLineIds on its own. (Until now the caller's viewport had to be the same)
  - readJumpFloodSteps(distance): list of jump flooding steps. (From the largest down to 1)
- ToonScreenOutline per-ID line color: setLineColor(lineId, color), removeLineColor(lineId), clearLineColors(), getLineColorCount(). (The Unreal Custom Stencil form, the color is picked by the ID already in the line target) The table is a 128 x 128 lookup texture covering every line ID, so there is no limit on how many are set.
