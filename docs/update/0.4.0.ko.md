# 0.4.0

## 요약

- 폴더 정리: src/experimental 에 있던 다 자란 기능(3D, 툰 3D, 애니메이션, 컬렉션 등)을 러스트 vanilla-engine 과 같은 폴더로 옮겼다. import.js 로 쓰던 게임은 그대로 돌고, 파일 경로로 직접 import 하던 게임은 새 경로로 바꾼다.
- 게임에서 엔진으로: 출시 게임들(외계행성 광부, aberrant, 종말 생존, 우주생물, 찾았다)이 따로 만들어 쓰던 범용 기능을 엔진 기본으로 넣었다. 창 쌓기(UIWindowLayer, UIWindow, UIConfirmWindow), 로딩, 저장, 시간(AssetLoader, LoadingProgress, LocalStorage, PersistedStore, FixedStepper), 입력 동작(InputActions), 소리 표(SoundSystem), 언어 묶음과 글꼴(LanguagePack, UIFont), 단추와 알림 모션(ButtonMotion, ToastMotion), 마우스 커서(PointerCursor) 같은 것이다.
- 툰 3D: 툰 셰이딩과 화면 공간 바깥선(ToonScreenOutline)을 실시간 툰 렌더링의 정석 꼴로 다시 지었다. 툰 효과(ToonVfx), HDR 마무리(ToonPostProcess), 그림자 아틀라스(ShadowAtlas)도 있다.
- 렌더링: 묶어 그리기와 화면 밖 거르기를 기본으로 켰다. 엔진 루프 밖에서 Graphic 을 직접 쓰는 코드는 그린 뒤 flushSpriteBatch() 를 부른다.
- 러스트 판과 맞추기: 러스트 판에만 있던 범용 기능을 들여와 두 엔진의 공개 API 를 맞췄고, 두 엔진에 같이 있던 버그를 같이 고쳤다.
- UI: UIInputField 가 크롬처럼 낱말 이동과 지우기, 낱말 경계를 다루고, 크롬 textarea 같은 여러 줄 입력(setMultiline)과 엔진 되돌리기, 다시 하기를 한다. UIDocument 는 등록한 이름으로 적어 줄인 번들에서도 같은 문서가 되고, registerEditorTypes() 로 UI 에디터의 종류를 한 번에 등록한다.
- Scene 과 Engine: 씬 꼴과 상관없이 노드의 위젯이 터치를 받는다. 씬마다 그리기 앞에 뷰 좌표를 걸어, Scene 을 바로 이은 씬이 기기 픽셀 배율 2 화면에서 캔버스 왼쪽 위 1/4 에만 그리던 것을 고쳤다.
- 문서: 사이트가 판마다 문서를 지을 자료(공개 API docs/api/0.4.0.json, 가이드 docs/guide/0.4.0)와 뽑는 도구 tools/apidoc.cjs 를 둔다.
- 옮길 것: 공개 API 나 쓰임이 바뀐 곳은 그 줄에 옮기는 법을 적었다. (Scene 터치, FbxLoader 이름, 씬 그리기 좌표, Singleton, Color, JsonAsset.load, List 와 Dictionary 의 콜백, ToonScreenOutline, 툰 셰이딩, isVisible, ToonVfx 자리, 그림 경로, Scene 배경, viewScaleMode 기본)

Enter 는 줄을 넣고(제출하지 않는다), 위아래는 첫 위아래 이동의 가로 자리를 지키고, PageUp, PageDown, Home, End(보이는 줄의 앞과 끝), Ctrl(맥은 Cmd) + Home, End(맥은 위, 아래)와 맥의 Home, End, PageUp, PageDown 넘기기는 러스트 판과 같다. 넘치면 커서가 보이게 스크롤하고 휠과 썸 끌기로 넘기며 썸을 그린다. 클래식 스크롤 막대(윈도우, 리눅스, 맥 클래식 설정)는 크롬 textarea 처럼 넘칠 때 막대 두께만큼 글 폭을 던다. setLineHeight(null 이면 CSS normal), setTabSize(기본 8), getScrollTop, setScrollTop 을 더했다. 되돌리기와 다시 하기는 캔버스 모드와 DOM 입력 모두 엔진 이력이다(Ctrl(맥은 Cmd) + Z, Ctrl(맥은 Cmd) + Shift + Z, 윈도우와 리눅스는 Ctrl + Y, 윈도우는 Alt + Backspace 도, 이어 친 글자는 한 묶음, 커서를 옮기면 끊기고, 붙여넣기와 잘라내기는 따로 한 묶음, 최대 1000). DOM 입력은 브라우저 되돌리기 키와 historyUndo, historyRedo 를 막고 엔진 이력으로 해서 문맥 메뉴로 붙여넣은 것도 되돌린다. IME 조합 중에는 되돌리지 않고, 확정한 글은 앞 글자 넣기 묶음에 붙는다. canUndo(), canRedo() 를 더했다. setText 는 목록을 비운다

- Engine: 최대 FPS 제한(EngineConfiguration.maximumFramePerSecond)을 처리한 프레임 수로 센다. 세기 시작한 때부터 처리한 프레임 수로 다음 프레임의 차례(시작 시각 + 수 × 간격)를 정하고, 차례보다 4 ms 넘게 일찍 온 프레임만 건너뛴다. 밀린 것은 다음 프레임에 처리해 평균이 최대 FPS 가 된다. 지금까지는 마지막으로 처리한 프레임 뒤로 간격보다 4 ms 덜 지났으면 건너뛰고 기준을 처리한 프레임의 시각으로 다시 잡아 밀린 것을 잊었으므로, 주사율이 최대 FPS 로 나누어떨어지지 않으면 제한이 어긋났다. (60 FPS 에서 90 Hz 는 한 프레임 걸러 45, 144 Hz 는 72, 75 Hz 는 하나도 건너뛰지 않아 75) 한 프레임 넘게 밀리면(창이 가려졌다 돌아옴 등) 몰아서 처리하지 않고 그 시각부터 다시 센다. 차례보다 1 ms 안쪽으로 일찍 온 프레임을 처리하면 그 시각부터 다시 세어, 주사율이 최대 FPS 와 거의 같은 화면(60.05 Hz 등)에서 조금씩 앞서 간 것이 쌓여 가끔 한 프레임을 건너뛰지 않는다. 최대 FPS 를 바꾸면 다시 센다. 60 Hz 화면의 60 FPS, 주사율의 약수인 최대 FPS(90 Hz 의 30 FPS 등)는 지금까지와 같다.

  - 1 을 넘는 해나 센 점광을 쓰던 장면은 화면이 바뀐다. (HDR 블룸에 센 빛을 쓰던 것) 지금까지 모습은 setLightIntensityLimited(false)
